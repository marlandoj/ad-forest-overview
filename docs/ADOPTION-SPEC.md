# Coverage-gap review → AD Forest Overview: adoption specification

Status: read-only scoping analysis for a possible Populate-ADForestOverview v1.5. No collector, template, production system or supplied input was changed. This is not an implementation or a live-forest validation.

## 1. Decision in brief

The default v1.5 scope should be existing-table completion: generic optional-feature name/state/scope, and five missing FGPP security settings. It does not require additional per-DC fan-out or a new module. New namespace, PKI, OS-demographic, topology-detail and inheritance content is opt-in and explicitly separated from that default. Detailed hardware, raw service catalogues, account hygiene, member identities and operations data stay out of the overview.

The staged comparison overstates the reference script's DNS/DHCP/Exchange breadth: this pinned script documents DC NIC DNS/DHCP-client settings and Exchange schema markers, not DHCP-server scopes/leases or a running Exchange organisation. Its event-log output is log names and configured maximum capacity, not event records. It generates no topology diagrams. See §§4, 8–10.

Authority: this file and coverage-inventory.json/csv supersede the exploratory forest-sites/domains/dcs/other inventories and notes. The latter preserve review provenance, including corrections, but are not independent build scope. An ADOPT-OPTIONAL is off by default behind a named proposed switch; it is not approval to expand v1.5 by default.

## 3. Enumeration and classification rules

- Inventory unit: one semantic displayed property for a scoped population. A multi-valued list is one property; unknown live row counts are not field counts. Old/new GPO alternatives and Word/text/HTML repetitions are not separate fields. Forest/domain/DC repeated facts and inverse FSMO views are linked as aliases in JSON. Exact named schema probes are records in a three-column schema-probe table, listed below. Numeric and friendly schema-release subfields are separately shown, clearly marked as presentation rather than separate directory reads.
- A derived FGPP enabled/not-enabled/manual-unlock mode is included in the corresponding numeric property, not silently omitted or counted as a second AD property. The inventory method/field explains it. OS bucket counts and domain totals, all-user/enabled-user denominators, and different privileged-group populations remain distinct. This is a declared denominator, not a universal metric of script complexity.
- CAPTURED: explicitly retained/exported AND mapped somewhere in the DOCX; a second blank destination is not a missing fact. A join of rendered DC role and identity/site rows counts as the same holder relationship. Conditional subset coverage is disclosed, not called full coverage.
- TEMPLATE-ONLY: an actual semantic slot exists but there is no retained automatic value. EVIDENCE-ONLY: retained JSON/CSV fact lacks full document rendering. When both a slot and exported value exist, EVIDENCE-ONLY takes precedence. ABSENT: no retained semantic value and no dedicated semantic slot. A generic Notes or free-form annex can be a proposed placement without pretending the exact field is already templated. Rich transient AD objects, a requested-but-discarded property and a different-population total are not evidence coverage.
- Schema probe names/intended-use labels use T15's existing extension/vendor semantics, so they are TEMPLATE-ONLY; presence lacks a dedicated column and is ABSENT. The proposed separate marker table intentionally preserves T15's human approvals and dates.
- Counts below are source/template coverage, not actual forest object counts, successful runtime tests or guaranteed ACL visibility. Blank/denied/unsupported is not false, zero or absent. Diagnostics and report metadata are separately counted so they cannot inflate infrastructure coverage.

### Limits and unresolved cases

All technical rendering regions were reviewed, including switch-gated hardware/services/user detail, repeated summaries and both GPO paths. Generic formatting utilities, their example tables, blank spacer/group labels, TOC/page numbering and fixed prose are layout rather than AD facts. Cover/property values are separately enumerated below; arbitrary content Word's installed building-block template may supply cannot be enumerated from this script alone. ScriptInfo/Dev logs, console verbosity and email transport are not document fields and are excluded. Diagnostic table below enumerates the forest/CA/site/feature branch messages as representative output states, not each repeated literal error sentence in every format; other read failures are covered by their associated field's failure/unknown contract rather than additional infrastructure properties.

No infrastructure row is left UNCLASSIFIED under these rules. Runtime differences, visibility of empty reads, exact costs and Windows/DC reachability remain untested. Static inspection cannot prove the document opens/rendering succeeds. CAPTURED never means service health, Windows PowerShell 5.1 certification or production verification. Formal PS AST/OOXML schema/runtime gates were unnecessary for an unchanged-source analysis and were not run.
